# 垂直切片工单模板与写作规范

## 通用写作规则

- **面向行为,不面向层。** 描述"哪一条端到端行为跑通"、从用户视角写——不是逐层的实现清单("加个表、加个接口"是反面案例)。
- **验收标准必须可客观验证。** 每条都应能由不了解上下文的人(或 agent)照着判定通过/失败。写行为断言("用 X 登录后能看到 Y"),不写实现断言("使用了 Redis")。
- **避免具体文件路径和代码片段**——它们过时得很快。

## 文件模板

```markdown
# <NN>-<title>

**来源:** 指向来源 spec 路径、issue 编号或 URL，没有可省略。

**被谁阻塞:** 它所依赖的工单的 <编号—标题> , 或<None — can start immediately>。

**要构建什么:** 这张工单让哪一条端到端行为跑通,从用户的视角描述。

**验收标准:**
  - [ ] 验收标准 1
  - [ ] 验收标准 2
```

## 示例:一次拆分长什么样

```
01 — 预重构:抽出 ReportSerializer
    来源：<spec 路径>
    被谁阻塞: None — can start immediately
    要构建什么:现有 JSON 报表行为不变,序列化逻辑收敛到单一入口,导出格式可插拔。
    验收标准:
      - [ ] 现有报表接口响应与重构前逐字节一致

02 — 单张报表导出 CSV
    来源：<spec 路径>
    被谁阻塞: 01 — 预重构:抽出 ReportSerializer
    要构建什么:用户在报表页点「导出 CSV」,下载的文件内容与页面所见一致。
    验收标准:
      - [ ] 报表页出现「导出 CSV」按钮
      - [ ] 下载文件的行列与当前筛选条件下的页面数据一致
      - [ ] 含中文与逗号的字段被正确转义

03 — 批量导出多张报表
    来源：<spec 路径>
    被谁阻塞: 02 — 单张报表导出 CSV
    要构建什么:用户勾选多张报表后一次导出 zip 包。
    验收标准:
      - [ ] 勾选 N 张报表导出,zip 内含 N 个 CSV
      - [ ] 单张失败不阻断其余,失败项在结果中列明
```

**注意示例体现的判断:**
1. 预重构在最前;
2. 除了预重构外，都是贯穿 UI→API→Service→Repo 的完整垂直切片，而非"先做后端";
