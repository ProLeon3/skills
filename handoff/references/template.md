# 交接文档模板

按任务选择或合并章节，省略无内容的章节。短交接只保留目标、当前状态、约束和下一步，不要填空节或凑行数。

---

# Handoff：{项目/任务名}

> 生成时间：{YYYY-MM-DD HH:mm}
> 原会话主题：{一句话}
> 下一会话重点：{用户参数原文；未提供则写"通用交接"}

## 1. 任务目标
用户最终想要什么。1–3 句，写"目的"而非"过程"。

## 2. 当前状态（基于取证，非记忆）
- 分支：{branch}，最近提交：{hash + message}
- 未提交改动：{git status 摘要，或"工作区干净"}
- 运行中的服务/进程：{或"无"}
- 完成度：{已完成 X / 进行中 Y / 未开始 Z}

## 3. 关键决策及理由
每条格式：**决策** → 理由 → 被否掉的备选方案（如有）。
这是文档中最有价值的部分，其他任何 artifact 里都没有。

## 4. 踩过的坑 / 失败的尝试
写明"试过什么、为什么不行"，防止下一个 agent 重蹈覆辙。

## 5. 未落盘的约定与用户偏好
口头达成但没写进任何文件的约定；用户的明确要求与禁令
（如"不要动 legacy 目录"、"提交信息用英文"）。

## 6. 下一步行动（按优先级）
每条必须具体到可直接执行：
1. {动作 + 涉及文件 + 预期结果}
2. …

## 7. 参考资料（引用，不复制内容）
- 规格/计划：{路径}
- 相关 issue / ADR：{编号或 URL}
- 关键代码文件：{路径 + 一句话说明看什么}
- 关键 commit：{hash + 说明}

## 8. 建议调用的 Skills
只列**当前环境真实存在**的 skill。每条格式：
- `{skill 名}`：{在哪一步用、为什么用} 。不确定是否存在的，不要写。

## 9. 环境与前置条件
- 需要的环境变量 / 配置（只写名称和获取途径，不写值）
- 依赖安装、数据库迁移等前置步骤
- 无特殊要求时省略本节
