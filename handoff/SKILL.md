## 执行流程

### 第 1 步：取证

只核对会影响接续工作的当前状态：

- git 的分支、未提交改动、最近提交
- 本会话启动或依赖服务时，核对相关进程和端口

### 第 2 步：撰写文档

- 需要组织复杂交接时参考 `references/template.md`；短任务直接写目标、当前状态、约束和下一步
- 读取 `references/redaction.md`，对全文执行脱敏
- 用户传入了参数：将参数视为"下一个会话的重点"，据此裁剪内容——与重点相关的写细，无关的一笔带过
- 用户未传参数：生成覆盖全局的通用交接文档

**内容取舍原则：**

已有材料给路径，只内联无法从其他地方取得的事实，例如：

| 必须内联（其他地方没有） | 只引用不复制               |
|---|----------------------|
| 决策及其理由 | spec / 计划文档 → 文件路径   |
| 失败过的尝试和原因（防止重蹈覆辙） | ADR / issue → 文件路径或 URL |
| 口头达成但未写入任何文件的约定 | 已提交的代码 → commit hash |
| 用户的偏好和明确禁令 | 大段 diff → 文件路径       |

篇幅按接续所需信息确定，不凑行数。

### 第 3 步：保存

- 目录：`/tmp/handoffs/`（不存在则创建）。**不要**存进当前 workspace（避免污染仓库）
- 文件名：`{项目名}-{YYYYMMDD-HHmm}.md`，例如 `payment-service-20260725-1430.md`。不要覆盖已有文件

### 第 4 步：自检

保存前逐条确认：

- [ ] 一个零上下文的 agent 只读此文档，能否不提问就开始干活？
- [ ] "下一步行动"是否具体到可执行（而非"继续优化"这类空话）？
- [ ] 所有引用的文件路径 / commit / URL 是否真实存在？
- [ ] "建议调用的 skills" 是否全部来自当前环境真实可用的 skill 列表？
- [ ] 脱敏是否完成，且没有因脱敏丢失必要的指路信息？

### 第 5 步：向用户回报

输出以下内容（缺一不可）：

1. 文档的**绝对路径**
2. 一行内容摘要（本次交接覆盖了什么）
3. 一句可直接粘贴到新会话的启动指令，例如：
   > 请读取 `/tmp/handoffs/payment-service-20260725-1430.md`，按其中"下一步行动"继续工作。
